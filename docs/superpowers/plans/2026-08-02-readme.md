# Developer README Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a detailed root README that lets a developer understand, install, collect data for, run, test, and safely contribute to the TR League of Legends item-statistics project.

**Architecture:** The root README is the developer onboarding entrypoint. It contains the complete local path from clone to a current-patch publication and running web UI, while linking to the existing design and operations documents for deeper methodology and production details. All commands, variables, endpoints, and claims are derived from checked-in scripts and source behavior.

**Tech Stack:** Markdown, Bun workspaces, TypeScript, Next.js, PostgreSQL 17, Drizzle ORM, Vitest, Playwright, Docker Compose, Riot League-V4/Match-V5, Data Dragon

## Global Constraints

- Audience: developers running and contributing locally.
- Production deployment remains summarized and linked to `docs/operations/collector.md` and `docs/operations/web.md`; do not duplicate the full runbooks.
- Scope is exactly TR1, Ranked Solo/Duo queue `420`, Emerald through Challenger at collection time, current TR Data Dragon major/minor patch, and an explicitly selected role.
- Results cover completed core items, unordered two-item and three-item multisets, and upgraded boots in a separate view.
- Describe statistics as correlation, not causal recommendations.
- Never include a real Riot key, PUUID, database credential, private error, or production connection value.
- Use only commands and environment variables that exist in the repository.
- State that PostgreSQL-gated and browser E2E tests are not executed by `bun run test` when their required test database is absent.
- Preserve the exact Riot legal notice rendered by the web application.
- Use repository-relative Markdown links so the README works on GitHub.

- [ ] **Step 3: Document statistical interpretation**

Add a `## What the statistics mean` section defining:

```text
Raw win rate = wins with the item or combination / sample
Build rate = sample / eligible champion-role games
Baseline difference = raw win rate - champion-role baseline win rate

Recommendation threshold = 100 games
```
